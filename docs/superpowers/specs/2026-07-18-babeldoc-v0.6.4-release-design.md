# BabelDOC v0.6.4 同步与插件 v0.0.25 发布设计

## 目标

将本项目使用的 BabelDOC 后端基线从 v0.6.3 更新到官方 v0.6.4，记录可复现的后端版本，兼容新增加的 DeepSeek thinking 参数，并发布 Local Immersive Translate v0.0.25。

## 范围

本轮只同步 BabelDOC v0.6.4 对现有本地后端封装有直接影响的部分：

- 安装器默认安装 BabelDOC v0.6.4。
- 后端把模型配置中的 `thinking` 传给 BabelDOC 的 `OpenAITranslator`。
- 文档说明本轮同步的用户可见改进。
- 插件版本升级为 v0.0.25，并通过现有标签工作流发布。

不复制或提交被 `.gitignore` 排除的 `BabelDOC/` 工作目录，不改动 BabelDOC 上游源码，也不新增插件首选项界面字段。高级用户可在本地后端 JSON 模型配置中设置 `thinking`。

## 方案

### 后端版本管理

macOS/Linux 安装脚本中的 `BABELDOC_REF` 默认值，以及 Windows PowerShell 安装脚本中的 `BabelDocRef` 默认值，都设为 `v0.6.4`。环境变量或命令行参数仍可覆盖默认值，保留调试其他分支或版本的能力。

对新安装，安装器克隆官方仓库后检出 v0.6.4；对已有安装，安装器先获取标签，再检出 v0.6.4。这样新旧安装得到相同后端版本，不依赖执行安装时官方 `main` 的状态。

### thinking 配置传递

`local_babeldoc_server/server.py` 继续从选中模型的后端配置读取高级参数。在创建 `OpenAITranslator` 时增加 `thinking=model_cfg.get("thinking")`。未配置时传入 `None`，保持原有请求行为；配置为 `enabled` 或 `disabled` 时，由 BabelDOC v0.6.4 生成对应的 DeepSeek 风格请求体。

示例配置只在 DeepSeek 模型项中展示 `"thinking": "disabled"`，避免其他模型误用。此字段不进入 Zotero 插件保存和传输的 API Key 配置，不改变现有用户界面。

### 版本与更新说明

`package.json` 版本从 0.0.24 升至 0.0.25。新增 v0.0.25 更新说明，包含：

- 同步 BabelDOC v0.6.4；
- 为异常超大页面渲染设置像素预算，降低内存耗尽风险；
- 修复 Latin/CJK 混排译文可能发生的行重叠；
- 支持 DeepSeek thinking 高级配置；
- 说明受影响 PDF 升级后可能产生纵向排版不同但更正确的输出。

### 测试与错误处理

后端单元测试使用替身 `OpenAITranslator` 捕获构造参数，验证配置的 `thinking` 会被传递，未配置时保持 `None`。安装器测试以文本级断言验证两个平台的默认版本都为 v0.6.4，避免平台间版本漂移。

发布前必须通过：

- `pnpm test`
- `pnpm lint:check`
- `pnpm build`

若任一检查失败，则修复并重新运行完整检查。在所有检查通过且工作区差异确认无误后，提交并推送 `main`。只有 `main` 推送成功后才创建并推送 `v0.0.25` 标签；标签触发现有 GitHub Actions Release 工作流。标签推送失败时不重写历史、不强制推送。

## 发布结果

预期 GitHub 仓库的 `main` 包含同步代码、测试和更新说明，`v0.0.25` 标签指向同一发布提交。GitHub Actions 构建 XPI 并创建对应 Release，现有插件更新地址继续使用仓库的发布资产。
