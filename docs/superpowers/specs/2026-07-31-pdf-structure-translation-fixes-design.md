# PDF 结构化翻译修复设计

## 背景

当前本地 BabelDOC 0.6.4 翻译链路存在三类可复现问题：

1. 部分表格只翻译标题，单元格文字保持原文；图片或扫描表格没有 OCR 回退。
2. `References`、`Bibliography` 等参考文献标题及其条目被当作普通正文翻译。
3. 目录条目在翻译时丢失独立行、层级缩进、点引导线和右对齐页码，译文被合并成连续段落。

修复必须默认启用，不能要求用户新增界面设置，并且在重新执行“安装/修复本地后端”后仍然生效。

## 目标与验收标准

### 表格

- 翻译带可提取 PDF 文字的表格标题、表头和单元格内容。
- 对没有足够可提取文字的图片或扫描表格，仅裁剪表格区域执行 OCR。
- 保留表格边框、底色、单元格范围和原始页面布局。
- 双语 PDF 的原文页保持原样；OCR 译文只出现在译文页。

### 参考文献

- `References`、`Bibliography`、`Works Cited`、`Literature Cited` 等独立章节标题保持原文。
- 从标题开始，参考文献条目全部绕过翻译模型和译文排版。
- 遇到明确的后续一级章节（例如 `Appendix`、`Supplementary Material` 或作者简介）时恢复翻译。

### 目录

- 翻译目录标题和每条目录的标题文本。
- 保留章节编号、层级缩进、逐条换行、点引导线和右对齐页码。
- 根据译文宽度重新生成点引导线，避免标题和页码重叠。

## 方案选择

采用本项目维护的 BabelDOC 下游兼容层，并增加按需表格 OCR。兼容层位于 `local_babeldoc_server`，由本地后端在 BabelDOC 中间表示完成布局识别后、进入翻译前调用。安装脚本负责安装和预热 OCR 依赖。

不采用以下方案：

- 仅修改模型提示词：无法恢复未解析文字、执行 OCR 或修复 PDF 坐标布局。
- 以 PP-StructureV3 替换整个解析链路：依赖和模型过重，跨平台部署、内存和现有 BabelDOC 回写集成风险过高。
- 直接编辑被忽略的 `BabelDOC/` checkout：安装器更新后会丢失，不是可交付修复。

## 架构

新增一个边界清晰的兼容模块，职责分为四部分：

1. `ReferenceSectionDetector`：按文档阅读顺序识别参考文献开始和明确结束边界，将对应段落标记为不可翻译。
2. `TocEntryProcessor`：检测目录页，把目录行解析为编号、标题、点引导线和页码，只把标题提交翻译，并用专用排版逻辑回写。
3. `NativeTableRecoverer`：在表格布局内恢复没有被现有布局模型纳入翻译的原生 PDF 文字，按边框、文本间距和视觉行生成单元格或文本块。
4. `RasterTableOcrProcessor`：只对缺少原生文字的表格区域进行 OCR，将 OCR 框映射到 PDF 坐标，翻译后在译文页面重建表格区域。

兼容层通过受版本检查保护的适配入口接入 BabelDOC 0.6.4。若 BabelDOC API 结构不符合预期，后端应在启动或任务创建阶段给出明确的不兼容错误，而不是静默跳过修复。

## 数据流

1. BabelDOC 解析 PDF 并完成页面布局检测。
2. 兼容层按阅读顺序标记参考文献区和目录页。
3. 表格恢复器处理原生文字表格；只有表格区域缺少足够原生文字时才调用 OCR。
4. 普通正文、目录标题和表格文本进入翻译队列；参考文献完全绕过翻译器。
5. BabelDOC 排版普通正文和原生表格文本；目录和 OCR 表格使用专用坐标回写逻辑。
6. 输出单语和双语 PDF，确保原文页未被 OCR 覆盖。

## 表格处理细节

### 原生文字

- 优先使用页面中的文字字符和表格边框坐标推断单元格。
- 有明确网格线时使用网格作为单元格边界；无线表格退化为视觉行和水平间距聚类。
- 已被 BabelDOC 正确识别的表格文本不重复创建，避免重叠翻译。
- 每个单元格或文本块有独立排版边界，译文不得越过单元格。

### 图片与扫描表格

- 使用轻量 ONNX OCR，仅渲染检测到的表格裁剪区域。
- OCR 返回文字框和置信度；低置信度结果保留原文并记录警告。
- OCR 框按裁剪缩放和 PDF 坐标系转换回原页。
- 译文覆盖使用区域背景采样或局部重建保留单元格底色，并保护网格线。
- OCR 模型在安装阶段安装和预热，运行任务时不应临时下载模型。

## 参考文献检测细节

- 标题匹配在去除空白和结尾标点后进行，要求短文本、独立段落和标题形态，避免正文中的普通引用触发。
- 支持 `References`、`Bibliography`、`Works Cited` 和 `Literature Cited`，大小写不敏感。
- 命中后，标题本身及后续条目保持原文。
- 只有明确的后续一级标题才结束跳过区；无法确认时以保持参考文献原文为优先。

## 目录处理细节

- 目录页由 `Contents` 或 `Table of Contents` 标题以及高比例的“章节号 + 标题 + 引导线 + 页码”行共同确认。
- 每条目录保存原始左边界、右边界、基线、字号、编号、页码和层级缩进。
- 只翻译标题文本；编号和页码不进入模型。
- 回写时编号锚定左侧，页码锚定原始右边界，标题放入中间区域，并根据剩余宽度生成点引导线。
- 译文过长时允许在标题区域内换行，但下一条目录仍从其原始或顺延后的独立基线开始，禁止合并条目。

## 配置与可观测性

三项修复默认开启，不新增 Zotero 首选项。后端 JSON 提供独立的高级开关用于兼容性回退：

- `enable_native_table_translation`
- `enable_table_ocr`
- `preserve_references`
- `preserve_toc_layout`

每个任务记录：检测到的表格数、原生表格恢复数、OCR 表格数、跳过的参考文献段落数、重建的目录条目数和低置信度 OCR 数。

## 错误处理

- 检测到图片表格但 OCR 未安装或模型不可用时，任务失败并返回明确错误，避免生成表格静默漏译的结果。
- 单个 OCR 文字块或单个目录标题翻译失败时，保留该块原文、记录警告并继续处理。
- PDF 解析、兼容 API 检查或 OCR 初始化失败时终止任务。
- OCR 仅处理表格区域，不对整篇 PDF 做无差别扫描。

## 测试策略

### 单元测试

- 参考文献标题和条目不调用翻译器，明确后续章节恢复翻译。
- 目录行正确拆分和重建，编号、缩进、页码和右边界不变。
- 原生表格恢复不重复处理已识别文字。
- OCR 裁剪坐标与 PDF 坐标双向转换正确。
- OCR 仅在表格原生文字不足时触发。

### 集成测试

- 使用仓库现有 U-Net PDF 验证表格文字翻译和参考文献保留。
- 使用仓库现有 49 页目录 PDF 验证目录结构。
- 增加图片表格夹具验证 OCR、译文覆盖和双语原文页保持。
- 使用假翻译器运行自动化测试，避免依赖外部 API。

## 非目标

- 不替换 BabelDOC 的通用页面布局模型。
- 不实现任意复杂电子表格到 Excel/HTML 的结构化导出。
- 不保证低分辨率、严重模糊或手写表格的 OCR 全部正确。
- 不改变 Zotero 任务提交、进度轮询、下载和附件导入协议。
