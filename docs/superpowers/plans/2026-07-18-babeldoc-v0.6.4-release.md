# BabelDOC v0.6.4 Sync and Plugin v0.0.25 Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Pin local installations to BabelDOC v0.6.4, pass its new DeepSeek thinking option through the local backend, and publish Local Immersive Translate v0.0.25.

**Architecture:** Keep BabelDOC as an external checkout managed by the existing cross-platform installers rather than vendoring upstream source. Record the supported tag in both installers, extend only the backend translator adapter for the optional setting, and document the upstream stability and layout fixes in a versioned release note.

**Tech Stack:** Python 3 `unittest`, Bash, PowerShell, TypeScript/Zotero plugin scaffold, pnpm, GitHub Actions.

## Global Constraints

- BabelDOC must default to the exact tag `v0.6.4` on macOS/Linux and Windows.
- Existing `BABELDOC_REF` and `BabelDocRef` overrides must continue to work.
- The Zotero preferences UI and request payload schema must remain unchanged.
- The release version must be exactly `0.0.25`, with Git tag `v0.0.25`.
- Do not commit the ignored `BabelDOC/` checkout or modify upstream BabelDOC source.
- Do not force-push or create the release tag before all local checks and the `main` push succeed.

```markdown
# Local Immersive Translate v0.0.25

## 后端同步

- 默认后端更新并锁定到 BabelDOC v0.6.4。
- 安装/修复操作会将现有 BabelDOC 工作目录更新到受支持版本。

- 上游为异常超大 PDF 页面增加单页光栅像素预算，降低布局检测和扫描件检测耗尽内存的风险。

## 兼容性说明

- 现有 Zotero 设置和模型 API 配置无需迁移。
- 行距修复会改变受影响页面的纵向排版，重新翻译后得到的 PDF 可能与旧版本不同。
```
